## How Wanted flows work (read this first)

| Step | Route | Core function | What it writes |
| --- | --- | --- | --- |
| Preview | `POST /wanted/preview` | `jobs.preview_run` | Review token (`verb=preview_run`) with `keys` = scoped rows |
| Grab | `POST /wanted/grab` | `jobs.matching_preview` → `jobs.grab_run` | `out/` via `run_fetch`; may auto-attach if `[ui].attach_mode = auto` |
| Attach (main) | `POST /wanted/attach` | `jobs.attach_run` | Zotero for `manifest.pending_attach()` keys |
| Attach (Advanced) | `POST /wanted/attach/preview` → Apply | `wanted_jobs.attach_preview` / `attach_apply` | Overrides for mismatch / short PDF |

**Scope rules** ([`paperful/ui/jobs.py`](../../paperful/ui/jobs.py) `scope_for_fetch`):

- Posted `keys` from the form → only those items.
- No keys → **Missing tab list only** (Have/Held excluded unless ticked).
- Row checkboxes use `name="keys"` and `form="wanted-form"` (see [`wanted.html`](../../paperful/ui/templates/wanted.html)).

**Attach count** ([`paperful/ui/pages.py`](../../paperful/ui/pages.py) `wanted_rows`):

```python
attach_pending = len([r for r in manifest.pending_attach() if r.itemKey in item_keys])
```

`pending_attach()` **excludes** records with `reason == strict_pdf_doi` or `short_pdf` unless Advanced flags allow them ([`paperful/store.py`](../../paperful/store.py)).

**Roadmap vs code (Oct 2026):** Grab `item_keys` and production `run_fetch` path are **already fixed** ([`test_grab_production_passes_item_keys`](../../tests/test_ui_grab.py)). Held row checkboxes are **not** `disabled` in the template. Still ship 1.1.1 for: tests that lock token scoping, Attach-at-zero UX, attach count honesty, version single-source, first-hour copy.

## Workstream A — Grab-selected + review token (tests)

### Goal

Preview of ticked rows → token `keys` exactly those rows → Grab fetches only those keys (not whole Missing list).

### Files

- [`paperful/ui/jobs.py`](../../paperful/ui/jobs.py): `preview_run`, `grab_run`, `matching_preview`
- [`tests/test_ui_grab.py`](../../tests/test_ui_grab.py)

### Do not break

- `grab_run` must pass `item_keys=list(keyset)` to both `run_fetch_fn` and `run_fetch` (lines ~249–306).
- `consume_review(..., keys=None)` is intentional: scope is the token’s stored `keys` + fingerprint, not a second key list.

### Add test: `test_preview_selected_keys_stored_on_token`

1. Two missing items `M1`, `M2`; one have item `H` (or anything not in Missing).
2. `preview_run(..., keys=["M1"], flags={})`.
3. Load review from `rec["review_token"]`.
4. **Assert** `review["keys"] == ["M1"]` (sorted).
5. `grab_run` with fake `run_fetch`; **assert** `item_keys == ["M1"]`.

### Add test: `test_preview_fingerprint_matches_ticked_subset_only`

1. Items `M1`, `M2` missing; preview only `M1`.
2. **Assert** fingerprint in token matches `scope_fingerprint([M1], manifest)`, not both.

### Add test (HTTP, optional but valuable): `test_wanted_grab_selected_posts_keys`

1. `TestClient`; monkeypatch `jobs.grab_run` to capture token.
2. `POST /wanted/preview` with `keys=M1`, wait/poll if needed, or call `preview_run` synchronously in test setup and post Grab with `grab_review_token`.
3. **Assert** consumed fetch scope is `M1` only.

### Pitfalls

- Empty `keys` list from form is falsy → routes use `keys or None` → Missing list. Do not treat `[]` as “all items”.
- `matching_preview` compares sorted `posted_keys` scope to `review["keys"]`; changing sort order in token creation must stay `sorted(keys)` in [`commands.create_review_token`](../../paperful/ui/commands.py).

## Workstream B — Held hand-ticks

### Goal

Users can tick **Held** rows for Preview/Grab/Attach-selected. Main Attach still **refuses** DOI mismatch / short PDF without Advanced.

### Product rules (do not guess)

| Held verification state | Checkbox | Preview/Grab when ticked | Main Attach (no Advanced) |
| --- | --- | --- | --- |
| `doi_mismatch` / `short` (held in manifest) | Enabled, default **unchecked** | Yes, if ticked | **No** — not in `pending_attach()` |
| `unverified` / `doi_match` with `STATUS_OK` pending | Enabled | Yes | Yes if in `pending_attach()` |
| `doi_match` in Zotero (Have tab) | Pre-**checked** (`row.ticked`) | Only if user keeps tick | N/A on Missing flow |

`row.ticked` is set only for `doi_match` in [`wanted_rows`](../../paperful/ui/pages.py) (~line 49).

### Files

- [`paperful/ui/templates/wanted.html`](../../paperful/ui/templates/wanted.html) — confirm no `disabled` on Held checkboxes
- [`paperful/ui/jobs.py`](../../paperful/ui/jobs.py) `attach_run`, `_attach_keys`

### Implementation notes

**Grab/Preview:** Already use posted `keys`; ticking a Held row includes it in `scope_for_fetch`. No code change unless tests fail.

**Attach selected:** `attach_run` filters `_attach_keys` through `pending_attach()` without allow flags. Ticking a Held **mismatch** key must **not** attach via main button (expected). Ticking Held **unverified** with `status=ok` and path must attach.

### Add test: `test_attach_selected_held_unverified`

1. Item `U1` in Held: manifest `Record(itemKey=U1, status=STATUS_OK, path=..., pdf_doi=None, doi=...)`.
2. `attach_run(cfg, keys=["U1"], collection=...)`.
3. Fake `attach_fn` records keys passed to pipeline.
4. **Assert** `U1` attached.

### Add test: `test_attach_selected_held_mismatch_skipped_on_main_button`

1. Item `M1`: `reason=REASON_STRICT_PDF_DOI`, `status=STATUS_OK`, path set.
2. `attach_run(cfg, keys=["M1"], ...)`.
3. **Assert** success false or zero attachments (today may return ok with no-op in `_attach_keys` — **prefer** explicit `no attachable PDFs` message when user posted keys but none pending).

### Pitfall

Do not widen main `attach_run` to pass `allow_pdf_doi_mismatch=True` — that belongs in Advanced [`wanted_jobs.attach_preview`](../../paperful/ui/wanted_jobs.py).

## Workstream C — Attach disabled at zero + count honesty

### Goal

When `counts.attach == 0` and user has not selected attachable rows, the main Attach button is **disabled** and cannot POST a no-op. When Attach runs, **number written == number promised** (label count or selected attachable pending).

### Files

- [`paperful/ui/templates/wanted.html`](../../paperful/ui/templates/wanted.html) — `#attach-btn`
- [`paperful/ui/static/workbench.js`](../../paperful/ui/static/workbench.js) — `updateToolbarLabels`
- [`paperful/ui/jobs.py`](../../paperful/ui/jobs.py) — `attach_run`, `_attach_keys`
- [`paperful/ui/wanted_routes.py`](../../paperful/ui/wanted_routes.py) — `wanted_attach`

### Template change

On `#attach-btn`:

```html
{% if counts.attach == 0 %}disabled{% endif %}
```

Also set `data-attach-count="{{ counts.attach }}"` for JS.

When user checks rows, JS may enable Attach only if **at least one ticked row is attachable**. For 1.1.1 minimal fix: if `counts.attach == 0`, keep disabled unless ticks present (then label becomes “Attach selected PDFs” — server must validate).

**Simpler 1.1.1 rule (recommended):** disable when `counts.attach == 0` **and** no row checkbox checked. If any checkbox checked, enable (server validates pending).

### JS change (`workbench.js`)

In `updateToolbarLabels`:

- Read `data-attach-count` from `#attach-btn`.
- `attachBtn.disabled = (attachCount === 0 && !any)` where `any` = checked row-select boxes.

Do not enable a disabled submit via `textContent` only.

### `attach_run` return value

Change signature to:

```python
def attach_run(...) -> tuple[bool, str, int]:
```

Return `(True, "", n)` where `n = len(pending)` actually passed to attach. On failure `(False, msg, 0)`.

Update `_attach_keys` to **return** `int` count (records with `pipe.attach_record` called, or len(pending) attached).

**Caller:** [`wanted_routes.py`](../../paperful/ui/wanted_routes.py) `wanted_attach`:

```python
ok, msg, n = jobs.attach_run(...)
if not ok: ...
if n == 0: return RedirectResponse(url=_page_url("/wanted", error="No attachable PDFs for that selection."), ...)
# optional: flash ?attached=n
```

### Tests

1. **HTTP** [`test_wanted_attach_route_and_button`](../../tests/test_ui_grab.py): extend — when `counts.attach == 0`, HTML contains `id="attach-btn"` and `disabled`.
2. **Unit:** manifest with 2 pending attachable → `attach_run(keys=[])` attaches 2, returns `n == 2`.
3. **Unit:** `attach_run(keys=["mismatch-held"])` → `n == 0`, `ok` is False with clear msg.

### Pitfall

Today `attach_run(keys=[])` with **no** pending returns `(False, "no keys selected")` — good. With pending, empty keys fills from all pending in collection — label must show `Attach N PDFs`.

## Workstream D — Version single-source + bind default

### Goal

One version string: [`pyproject.toml`](../../pyproject.toml) `project.version`. Runtime reads via `importlib.metadata`. CI fails if `paperful/__init__.py` duplicates a stale literal.

### Files

- [`paperful/__init__.py`](../../paperful/__init__.py) — replace `__version__ = "1.0.0"` with:

```python
def _version() -> str:
    try:
        from importlib.metadata import version
        return version("paperful")
    except Exception:
        # editable install without metadata
        import tomllib
        from pathlib import Path
        data = tomllib.loads(Path(__file__).resolve().parents[1].joinpath("pyproject.toml").read_bytes())
        return str(data["project"]["version"])

__version__ = _version()
```

- Bump `pyproject.toml` to `1.1.1`.
- [`tests/test_version.py`](../../tests/test_version.py) (new):

```python
import re
import tomllib
from pathlib import Path
from paperful import __version__

def test_version_matches_pyproject():
    root = Path(__file__).resolve().parents[1]
    expected = tomllib.load((root / "pyproject.toml").open("rb"))["project"]["version"]
    assert __version__ == expected

def test_init_has_no_stale_literal():
    text = (root / "paperful" / "__init__.py").read_text()
    assert not re.search(r'__version__\s*=\s*"[0-9]+\.[0-9]+\.[0-9]+"', text)
```

- Optional CI step in [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml): `uv run pytest tests/test_version.py`.

## Common mistakes (for weaker implementers)

1. **Fixing Grab by passing `keys=` to `run_fetch`** — wrong parameter name; use **`item_keys`**.
2. **Enabling mismatch attach on main button** — use Advanced only.
3. **Only disabling Attach in HTML** — user can still POST; enforce in `wanted_attach` + `attach_run`.
4. **Leaving `__version__ = "1.1.1"` literal** — defeats single-source; use metadata + test.
5. **Hiding auto-attach by deleting the setting** — hide UI only; respect existing `config.toml` `attach_mode`.
6. **Forgetting `form="wanted-form"`** — row checkboxes are outside the form; tests use POST body `keys=`.
