# 1.7 hardening + platform wave — decision log

Single public tag: **v1.7.0**. Scope is hardening-led + platform-led; new
product bets stay out (see `docs/ROADMAP.md` parked list).

## Baseline (Phase 0, measured 2026-11-02)

- Suite: 3,357 passed / 4 skipped; coverage 82.6% (gate 80).
- Wave end: 3,421 passed / 2 failed (both in the concurrent workbench UI
  template work, untouched by this wave) / 4 skipped; coverage 82.3%.
  The planned gate of 85 was **not** reached — new feature/UI code grew
  the denominator as fast as ~90 new tests grew the numerator — so the
  gate is set to 82 (up from 80) and 85 is deferred, not claimed.
- Lint: `ruff check` (narrow `F821` + curated `S*`), `ruff format --check`,
  `mypy` on 6 files — all green.
- Socket gate: `--disable-socket` run failed exactly 4 tests, all calling
  Crossref/OpenAlex/Semantic Scholar enrichment for real (stub patched the
  wrong module attribute). Fixed at the stub; gate is now CI-required.
- Dependency risks: `pyzotero` private `_upload.Zupload` subclass
  (`paperful/attach.py`), `lancedb<1`, `litellm<2`, `openxml-audit<1`,
  Binoculars git overlay. Playwright was a core dependency despite every
  import being function-local.

## Spike decisions (Phase 1)

| Spike | Decision | Why |
| --- | --- | --- |
| Playwright optional extra | **GO** — shipped as `paperful[browser]` | All imports are lazy; `doctor` already probes availability. Core + `[serve]` installs are lean; the Docker operator image still installs `--extra browser`, so the Compose path is unchanged. |
| Workbench token auth | **GO** — shipped | `PAPERFUL_UI_TOKEN` / `serve --ui-token` requires a bearer token on everything except `/health`. Loopback default is unchanged; this only hardens a deliberately exposed `--allow-remote-bind`. Single shared secret, no accounts. |
| OS keyring for secrets | **NO-GO for 1.7** | Headless/Docker operators (the tested install path) have no keyring daemon; env vars already work everywhere and `paperful config check` steers secrets there. Revisit only with tester demand. |
| Python lifecycle | **GO (additive)** | CI matrix gains 3.14. `requires-python >=3.10` is kept for 1.7 even though 3.10 is end-of-life, so existing installs are not stranded mid-wave; dropping it is a separate, announced change. |
| Adapter conformance kit | **GO** — Phase 4 | One parametrized contract suite over fake backends (Zotero/Mendeley/EndNote shapes). Promotion to "supported" still requires a real-library field report; the kit alone does not promote. |
| Signed desktop bundle | **NO-GO for 1.7** | Signing/notarisation cost and upkeep for a single maintainer outweighs reach while `pipx`/`uv tool` + Compose cover the tested routes. Documented as rejected, not deferred silently. |

## Install route (Phase 5 decision)

Public story: `pipx install paperful` / `uv tool install paperful` for the
CLI, Docker Compose for the operator workbench. Both are exercised by the
fresh-install CI job. `[serve]` without Docker is documented as-is (works,
but Compose is the path CI proves end to end).

## Adapter promotion criteria (written before field reports arrive)

A backend may be called **supported** only when all hold:

1. The conformance suite passes against its fake.
2. A completed `docs/templates/adapter-field-assessment.md` from a real
   library (list, fetch a missing PDF, attach, notes round-trip,
   failed-auth next-steps ladder) is filed under `assessments/`.
3. Mirror-first reads work with the manager closed.

Until then README/docs keep "seeking testers". If no reports arrive, 1.7
ships with that wording — an honest outcome, not a missed gate.

  built in one working tree and will tag `v1.7.0` once.
