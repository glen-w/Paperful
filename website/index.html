The application

See what’s missing, grow the collection, tidy the records, then ask the PDFs you already have.

What it does

Every fetch lands in a folder on this computer first: open-access copies when they exist, campus login when you have it, then you attach the files you trust. Zotero stays the catalogue. Optional notes and answers use a model only when you turn one on, and they point back at the PDFs you already hold.

The default nav is Wanted, Discover, Ask, Library, Activity, and System. Ask answers need optional AI turned on. ⚙️ marks Advanced; 🤖 marks optional AI (off until you enable it).

On your machine

Downloads, notes, peer-review packs, and the folder copy stay on this computer. Zotero remains the catalogue. Optional AI uses Ollama locally and stays off until you turn it on. You copy the folder yourself; Zotero stays the catalogue on this computer.

From a collection to PDFs you trust

  1. Open the workbench and pick a collection.
  2. On Wanted, preview what’s missing, then fetch copies onto your computer.
  3. Open the files yourself and attach the ones you trust. On Zotero 10 or newer you can attach from the workbench; Grab leaves copies in a folder until you do.
  4. Grow the library on Discover. Tidy records on Repair after you turn on Advanced.

Install

Keep Zotero open on the host with the local API enabled, then open the workbench at http://127.0.0.1:8765. Host install without Docker (PyPI): 

uv tool install "paperful[serve]"     # or: pipx install "paperful[serve]"
mkdir my-paperful && cd my-paperful
printf 'email = "you@university.edu"\n' > config.toml
paperful doctor
paperful serve                        # http://127.0.0.1:8765

Campus login / HTML PDF: install "paperful[serve,browser]". The uv tool line was run on a Linux box; pipx is the same shape. Prefer a container: 

git clone --branch v1.9.8 https://github.com/glen-w/Paperful.git
cd Paperful
cp .env.example .env
mkdir -p ../paperful-data ../paperful-out
cp config.minimal.toml ../paperful-data/config.toml   # set email
docker compose build
docker compose run --rm paperful doctor
docker compose up

Compose reads config.toml from PAPERFUL_DATA and the PDF mirror from PAPERFUL_OUT (the .env defaults are ../paperful-data and ../paperful-out), not from the git root. Set a real email in that file (Unpaywall). To keep data in the checkout, set PAPERFUL_DATA=. and PAPERFUL_OUT=./out, then copy config.toml next to compose.yaml. The guide and this page track main. pip and the v1.9.8 tag are the current release.
