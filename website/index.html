How it works

When you fill a collection, Paperful does this. Preview first from Install if you want to see the plan before anything is fetched.

  1. Pick the slice. A collection, or the whole library. You can narrow by year or item type.
  2. Look for a free copy first. Unpaywall, OpenAlex, arXiv, bioRxiv/medRxiv, Europe PMC, Semantic Scholar, CORE, then the item’s own URL. Web pages can be printed to PDF. Odd hosts use playbooks you write. Google Scholar and Sci-Hub stay off until you turn them on.
  3. Use your library login when you have it. Log in once in Chrome or Edge. Paperful reuses that campus session through EZProxy. Same pattern for Scholar if you opt in. The institutional password is never stored in config. When the campus session expires, that lane stops for the rest of the run.
  4. Only try what fits. A paper with a DOI does not get sent to every site. If a site says slow down, we wait. If it keeps blocking or showing a CAPTCHA, we pause that source and come back later so one publisher does not stall the run.
  5. Save on this machine first. The PDF lands on disk with a readable source line (“Free copy from Unpaywall.”). On Zotero 10+ it can attach; older Zotero still gets the file on disk. Not every paywalled paper comes back.

Around a fill. Before a messy ingest, review duplicates; nothing merges until you say so. After a fill, you can tidy identifiers and, if you want, write summary notes from the PDF text. How it works · Sources · Sessions · EZProxy · Dedupe.

What it does

  • Downloads. Missing PDFs, when a copy can be reached. Each attachment keeps a source line.
  • Notes. Optional grounded summary from the PDF’s text. Local model, off until you enable it. Scans need a text layer first.
  • Summaries. A collection-level review of those notes.
  • A folder copy. Snapshot on disk; export RIS, BibTeX, or EndNote XML. Copy that folder yourself — not a sync service.

You can also grow the library from a search or seed papers; that is a different step from filling PDFs you already keep. Snowball.

Your machine, your files

Paperful is a local tool. It reads your catalogue through an adapter — Zotero’s local API is the path that is well tested. Logins you make in the browser stay on this machine; the folder copy is yours to move.

Install

Build on your machine — there is no app store package and no published Docker image. Keep Zotero on the host with the local API enabled.

  1. Copy config.minimal.toml, add your email, and run paperful doctor.
  2. List collections and see which ones still need PDFs: paperful collections.
  3. Dry-run a collection, then fetch and attach.
  4. Optionally log in to EZProxy or Scholar on the host before a larger run. 
git clone https://github.com/glen-w/Paperful.git
cd Paperful
cp .env.example .env
cp config.minimal.toml config.toml
docker compose build
docker compose run --rm paperful doctor
docker compose run --rm paperful run --collection interesting --preset oa --dry-run
# campus: --preset eoi, after uv run paperful session login ezproxy on the host

Rename is not enough: edit .env (data directory, Zotero host, and image pack) and set a real email in config.toml. The minimal config is open-access sources only — paths, Zotero as manager, no campus EZProxy. .env.example sets PAPERFUL_IMAGE_MODE=heavy (llm / rag / browser-agent); CI builds light. .env / Docker · light vs heavy · config.toml.
